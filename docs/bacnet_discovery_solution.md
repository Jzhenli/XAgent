# BACnet 设备自动发现功能设计方案

## 📋 文档概述

**文档版本**: v1.0
**创建日期**: 2026-07-01
**方案目标**: 为 BACnet 南向插件添加设备和点位自动发现功能，提升配置效率

---

## 🎯 一、方案背景与目标

### 1.1 当前问题

**现状分析**：
- ✅ BACnet 插件已实现基本的读写功能
- ❌ 设备和点位配置完全依赖手动输入
- ❌ 配置效率低，需要逐个输入多个参数
- ❌ 已声明支持 `who_is/i_am` 但未实现

**用户痛点**：
```
典型场景：配置一个 BACnet 设备
  ├─ 需要手动填写：资产标识、设备名称、设备ID、主机地址、端口...
  ├─ 需要逐个配置：50+ 个点位（对象类型、实例ID、属性ID...）
  ├─ 耗时：30-60 分钟
  └─ 易错：参数输入错误导致配置失败
```

### 1.2 目标方案

**核心目标**：
1. **设备自动发现**：通过 Who-Is/I-Am 扫描网络中的 BACnet 设备
2. **点位自动发现**：读取设备对象列表，自动识别点位
3. **一键配置**：发现后快速添加，减少手动输入
4. **双模式支持**：同时支持手动配置和自动发现，把选择权交给用户

**效率提升预期**：
- 设备配置：从 5-10 分钟 → 30 秒（效率提升 10-20 倍）
- 点位配置：从 30-60 分钟 → 3-5 分钟（效率提升 10 倍）

## 🎨 二、核心设计理念

### 2.1 设计原则

**1. 用户自主权原则**
```
用户可以选择：
  ├─ 手动配置：适合专家用户，精确控制每个参数
  ├─ 自动发现：适合新手用户，快速批量配置
  └─ 混合使用：发现后可切换到手动模式微调
```

**2. 流程合理性原则**
```
错误流程：填写基础信息 → 选择协议 → 发现设备 ❌
  问题：基础信息可能无用

正确流程：选择协议 → 选择模式 → 配置/发现 ✅
  优势：避免无用操作，信息自动填充
```

**3. 兼容性原则**
```
要求：
  ├─ 不破坏现有设备添加流程
  ├─ 不影响其他协议（Modbus/KNX）的使用
  └─ 作为增强功能，而非替代功能
```

### 2.2 技术架构

**架构层次**：
```
前端 UI 层
  ├─ 协议选择界面
  ├─ BACnet 模式选择界面
  ├─ 设备发现界面
  └─ 点位发现界面
      ↓
后端 API 层
  ├─ 设备发现 API
  ├─ 点位发现 API
  └─ 批量添加 API
      ↓
服务层
  ├─ Discovery Service（独立服务）
  └─ 设备管理服务
      ↓
插件层
  ├─ BACnet Plugin（discover_devices/discover_points）
  └─ bacpypes3 库（Who-Is/I-Am）
```

### 7.2 技术风险评估

**风险点识别**：

```
1. 网络权限风险 ⚠️
   问题: Who-Is 广播需要网络权限，可能被防火墙阻止
   解决方案:
     ├─ 提供详细的网络配置指南
     ├─ 支持指定网络范围（避免广播）
     └─ 降级方案：手动配置仍可用

2. 设备兼容性风险 ⚠️
   问题: 部分设备不支持 objectList 读取
   解决方案:
     ├─ 降级策略：逐个探测对象实例
     ├─ 错误提示：明确告知用户
     └─ 部分发现：只发现支持的对象

3. 性能风险 ⚠️
   问题: 大量点位发现可能耗时较长
   解决方案:
     ├─ 进度实时反馈
     ├─ 分批次读取
     ├─ 用户可取消操作
     └─ 结果缓存

4. 用户混淆风险 ⚠️
   问题: 用户不清楚何时用手动/自动
   解决方案:
     ├─ 清晰的模式标注（新手/专家推荐）
     ├─ 流程引导提示
     └─ 文档和教程支持
```

## 🎯 八、方案总结

### 8.1 核心优势

**用户体验优势**：
```
✅ 避免无用操作：先选协议，再配置
✅ 信息自动填充：发现的设备信息自动填充基础字段
✅ 批量操作支持：一键批量添加设备/点位
✅ 双模式并存：手动配置和自动发现自由选择
✅ 流程清晰：步骤指示器 + 实时进度反馈
```

**技术架构优势**：
```
✅ 独立服务设计：Discovery Service 不污染插件实例
✅ 兼容现有流程：不破坏其他协议的设备添加流程
✅ 易于扩展：未来可支持 KNX 等其他协议的发现
✅ 性能优化：批量读取 + 并发控制 + 结果缓存
```

### 8.2 效率提升预期

| 操作场景 | 手动配置耗时 | 自动发现耗时 | 效率提升 |
|---------|------------|------------|---------|

| **点位配置（50个）** | 30-60 分钟 | 3-5 分钟 | **10倍** |
| **批量设备部署（10台）** | 50-100 分钟 | 5-8 分钟 | **10-12倍** |

### 8.3 实施建议总结

  └─ 用户反馈最快

第二步: 实现设备发现（价值中等，风险中等）

  ├─ 可能受环境限制
  └─ 手动配置仍可用（降级方案）

第三步: 优化增强（锦上添花）
