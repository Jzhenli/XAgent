## 1. 产品概述

### 1.1 简介

XAgent 是一款基于 Python + FastAPI 开发的轻量级跨平台 IoT 网关，用于工业设备数据采集、协议转换、规则处理与上行转发。系统采用插件化架构，南向对接多种工业协议，北向对接云端 / MQTT 平台，并通过规则引擎实现告警、联动控制等业务逻辑。

### 1.2 架构总览

```
┌────────────────────────────────────────────────────┐
│                     前端 Web UI                     │
└────────────────────────────────────────────────────┘
                          │ HTTP /api
┌────────────────────────────────────────────────────┐
│                  FastAPI 应用层                     │
│   (devices / rules / channels / users / logs …)    │
└────────────────────────────────────────────────────┘
                          │
┌────────────────────────────────────────────────────┐
│                    Gateway 核心层                   │
│  Container · Scheduler · EventBus · Lifecycle      │
└────────────────────────────────────────────────────┘
                          │
   ┌───────────────┬──────┴───────┬────────────────┐
   ▼               ▼              ▼                ▼
┌─────────┐   ┌──────────┐  ┌──────────┐  ┌──────────────┐
│  南向   │   │  过滤器  │  │ 规则引擎 │  │   北向通道   │
│ South   │ → │  Filter  │→ │   Rule   │→ │    North     │
│ BACnet  │   │  去重    │  │ 阈值/表达│  │  MQTT / XNC  │
│ Modbus  │   │  缩放    │  │ 调度     │  │              │
│ KNX     │   │  重命名  │  │          │  │              │
└─────────┘   └──────────┘  └──────────┘  └──────────────┘
                                  │
                                  ▼
                        ┌──────────────────┐
                        │  Delivery 投递   │
                        │ 邮件/Webhook/    │
                        │ 动作/系统告警     │
                        └──────────────────┘
```

### 1.3 核心特性

- **跨平台部署**：支持 Windows、Linux、Android（通过 PyApp 打包为原生 WebView 应用）
- **插件化架构**：南向、北向、过滤、规则、投递五大插件类型，支持热加载
- **多协议支持**：BACnet/IP、Modbus TCP/RTU、KNX
- **规则引擎**：阈值判断、表达式评估、定时调度，支持多级 Pipeline 与告警通道
- **数据存储**：SQLite + WAL 模式，写缓冲 + 定时清理
- **完整 RESTful API**：FastAPI 自动生成接口文档
- **Web UI**：内置 SPA 前端，支持登录、设备管理、规则配置、SCADA 组态

## 2. 安装与启动

### 2.1 运行环境

| 平台 | 要求 |
| --- | --- |
| Windows | Win10+，WebView2 Runtime |
| Linux | glibc 2.31+（推荐 Ubuntu 20.04+/CentOS 8+） |
| Android | Android 7.0+（arm64-v8a） |
| Python（开发模式） | Python 3.10+ |

### 2.2 命令行启动

```bash
# 模块方式启动
python -m XAgent

# 初始化默认配置文件（不启动服务）
python -m XAgent --init-config

# 指定数据目录、开启调试
python -m XAgent --data-dir /opt/xagent/data --debug

# 指定自定义配置文件
python -m XAgent --config /etc/xagent/config.yaml
```

**支持的启动参数**：

| 参数 | 说明 |
| --- | --- |
| `--config` | 配置文件路径 |
| `--data-dir` | 数据目录路径（覆盖环境变量 `APP_DATA_DIR`） |
| `--debug` | 开启 DEBUG 模式，打印详细日志 |
| `--init-config` | 生成默认配置文件并退出 |

### 2.3 PyApp 打包运行

```bash
# Windows
pyapp build windows
pyapp run windows -u          # 更新源码后运行
pyapp package windows         # 完整打包

# Linux（aarch64）
pyapp build linux --arch aarch64

# Android
pyapp build android --arch arm64-v8a
```

### 2.4 默认端口

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| HTTP API + Web UI | `18080` | 主服务端口 |
| Metrics | `9090` | 指标暴露端口（需配置启用） |

启动成功后访问 `http://<主机IP>:18080` 即可进入 Web UI。

## 3. 配置管理

### 3.1 配置文件位置

XAgent 使用 `platformdirs` 自动管理路径：

| 平台 | 默认配置目录 |
| --- | --- |
| Windows | `C:\Users\<用户>\AppData\Local\adveco\XAgent\config\config.yaml` |
| Linux | `~/.local/share/XAgent/config/config.yaml` |
| macOS | `~/Library/Application Support/XAgent/config/config.yaml` |

可通过以下方式覆盖：

1. 命令行 `--data-dir`
2. 环境变量 `APP_DATA_DIR`
3. 命令行 `--config` 指定具体文件

### 3.2 配置文件结构

```yaml
# 服务器配置
server:
  host: "0.0.0.0"
  port: 18080
  debug: false

# 日志配置
logging:
  level: "INFO"                                  # DEBUG / INFO / WARNING / ERROR
  format: "%(asctime)s - %(name)s - %(levelname)s - %(message)s"
  file: "${log_dir}/xagent.log"                  # 支持路径占位符
  max_bytes: 10485760                            # 10 MB
  backup_count: 5
  console: true
  date_format: "%Y-%m-%d %H:%M:%S"
  color: true

# 存储配置
storage:
  type: "sqlite"
  database: "${data_dir}/xagent.db"
  wal_mode: true                                 # WAL 模式提升并发
  batch_size: 100
  flush_interval: 5                              # 秒
  retention_days: 1                              # 历史数据保留天数，0 表示不清理
  cleanup_interval: 300                          # 清理任务执行间隔（秒）
  cleanup_batch_size: 10000

# 插件配置
plugins:
  failure_strategy: continue                     # continue / abort
  allow_partial_startup: true                    # 是否允许部分插件启动失败
  south: []
  north: []
  filter: []

# 调度器
scheduler:
  max_workers: 10
  task_timeout: 30

# 指标
metrics:
  enabled: true
  port: 9090
```

### 3.3 路径占位符

配置文件中支持以下路径变量：

| 占位符 | 含义 |
| --- | --- |
| `${config_dir}` | 配置目录 |
| `${data_dir}` | 数据目录 |
| `${log_dir}` | 日志目录 |
| `${cache_dir}` | 缓存目录 |

### 3.4 配置热加载

XAgent 内置配置监控任务（每 5 秒检查一次），主配置文件修改后会自动重载；日志级别变更会即时生效，无需重启服务。

### 3.5 API Token 鉴权

涉及写操作的 API 需通过 Bearer Token 鉴权：

- 默认 Token：`xagent_47808`
- 通过环境变量 `XAGENT_API_TOKEN` 覆盖

请求示例：

```http
GET /api/devices HTTP/1.1
Authorization: Bearer xagent_47808
```

## 4. 快速入门

### 4.1 启动流程

1. 执行 `python -m XAgent --init-config` 生成默认配置文件
2. 启动服务：`python -m XAgent`
3. 浏览器访问 `http://localhost:18080`
4. 使用默认账号登录（首启会创建默认管理员，详见 [10. 用户与权限](#10-用户与权限)）

### 4.2 数据接入三步走

**第一步：添加南向设备**

通过 Web UI 或 API 创建一个 Modbus TCP 设备：

```bash
curl -X POST http://localhost:18080/api/devices/ \
  -H "Authorization: Bearer xagent_47808" \
  -H "Content-Type: application/json" \
  -d '{
    "asset": "modbus_device_001",
    "name": "1号Modbus设备",
    "plugin": {
      "name": "modbus_tcp",
      "config": {
        "host": "192.168.1.10",
        "port": 502,
        "slave_id": 1
      }
    },
    "points": [
      {
        "name": "temperature",
        "data_type": "float",
        "unit": "°C",
        "config": {"function_code": 3, "address": 0, "quantity": 2, "byte_order": "big", "register_type": "holding"}
      }
    ]
  }'
```

**第二步：配置北向通道（可选）**

将采集数据上行到 MQTT Broker：

```bash
curl -X POST http://localhost:18080/api/channels/ \
  -H "Authorization: Bearer xagent_47808" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "mqtt_channel_01",
    "name": "主MQTT通道",
    "protocol": "mqtt",
    "enabled": true,
    "config": {
      "broker": "mqtt.example.com",
      "port": 1883,
      "username": "user",
      "password": "pwd",
      "topic": "xagent/data",
      "qos": 1
    }
  }'
```

**第三步：观察数据**

- 访问 Web UI 的 Dashboard 页面查看实时数据
- 通过 `GET /api/data/readings?asset=modbus_device_001` 查询历史数据
- 访问 `http://localhost:18080/api/stats` 查看采集统计

## 5. 插件体系

XAgent 插件分为五大类型，目录结构对应 `XAgent/plugins/`：

| 类型 | 目录 | 职责 |
| --- | --- | --- |
| South（南向） | `plugins/south/` | 对接现场设备协议，采集数据 |
| North（北向） | `plugins/north/` | 对接云端 / 上行平台 |
| Filter（过滤器） | `plugins/filter/` | 在数据流转过程中进行处理 |
| Rule（规则） | `plugins/rule/` | 触发条件评估 |
| Delivery（投递） | `plugins/delivery/` | 规则触发后的通知/动作执行 |

### 5.1 南向插件（South）

#### 5.1.1 BACnet/IP

**插件名**：`bacnet`

**用途**：连接 BACnet/IP 设备，读取对象属性、下发控制命令

**关键配置**：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `host` | `localhost` | 设备 IP |
| `port` | `47808` | BACnet 标准端口 |
| `device_id` | `100` | 设备 ID |
| `timeout` | `3.0` | 通信超时（秒） |
| `interval` | `5` | 轮询间隔（秒） |
| `reconnect_interval` | `5` | 重连间隔（秒） |
| `heartbeat_mode` | `device_object` | 心跳模式：`device_object` / `none` |
| `heartbeat_property` | `objectName` | 心跳读取的属性 |
| `heartbeat_timeout` | `5.0` | 心跳超时 |
| `heartbeat_retries` | `3` | 心跳重试次数 |
| `point_timeout` | `3.0` | 点位读取超时 |
| `point_retries` | `2` | 点位读取重试 |
| `max_concurrent_reads` | `20` | 最大并发读取数 |
| `batch_read_enabled` | `true` | 是否启用批量读取 |
| `batch_size` | `50` | 批量大小 |

**点位 `config` 字段示例**：

```json
{
  "object_type": "analogInput",
  "object_instance": 1,
  "property": "presentValue"
}
```

**特殊能力**：支持 Who-Is/I-Am 设备发现、ReadPropertyMultiple 批量读取、点位自动发现。

> ⚠️ Linux 平台依赖 `bacpypes3==0.0.106`，BACnet 设备发现总超时为 60 秒。

#### 5.1.2 Modbus TCP

**插件名**：`modbus_tcp`

**关键配置**：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `host` | `127.0.0.1` | 设备 IP |
| `port` | `502` | Modbus TCP 端口 |
| `slave_id` | `1` | 从站 ID |
| `timeout` | `3` | 通信超时（秒） |
| `reconnect_interval` | `5` | 重连间隔（秒） |
| `heartbeat_address` | `null` | 心跳寄存器地址 |
| `heartbeat_timeout` | `1.5` | 心跳超时（秒） |
| `max_gap` | `5` | 寄存器最大间隔（影响自动分组） |

**依赖**：`pymodbus`

#### 5.1.3 Modbus RTU

**插件名**：`modbus_rtu`

**关键配置**（除 Modbus TCP 通用项外）：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `serial_port` | `/dev/ttyUSB0` | 串口设备路径（Windows 示例：`COM3`） |
| `baudrate` | `9600` | 波特率 |
| `parity` | `N` | 校验位：N / E / O |
| `stopbits` | `1` | 停止位：1 / 2 |
| `bytesize` | `8` | 数据位：7 / 8 |

**依赖**：`pymodbus` + `pyserial`

#### 5.1.4 KNX

**插件名**：`knx`

**关键配置**：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `gateway_ip` | `192.168.1.100` | KNX 网关 IP |
| `gateway_port` | `3671` | 网关端口 |
| `local_ip` | `null` | 本地 IP（多网卡时指定） |
| `route_back` | `false` | 路由回传 |
| `connection_type` | `automatic` | 连接模式：`automatic` / `tunneling` / `tunneling_tcp` / `routing` / `tunneling_tcp_secure` / `routing_secure` |
| `interval` | `5` | 轮询间隔（秒） |
| `sync_mode` | `smart` | 同步模式：`passive` / `always` / `smart` |
| `sync_interval` | `60` | 同步间隔（秒） |
| `max_concurrent_syncs` | `5` | 最大并发同步数 |

**依赖**：`xknx`

> 💡 当 KNX 网关连接数满时，可改用 `routing` 模式（多播通信，不占用连接槽）。

### 5.2 北向插件（North）

#### 5.2.1 MQTT 客户端

**插件名**：`mqtt`

**用途**：将采集数据发布到 MQTT Broker，并订阅下行命令主题

**关键配置**：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `broker` | - | Broker 地址 |
| `port` | - | Broker 端口 |
| `username` | `null` | 用户名 |
| `password` | `null` | 密码 |
| `client_id` | 自动生成 | 客户端 ID |
| `topic` | - | 数据上行主题 |
| `command_topic` | - | 命令下行订阅主题 |
| `qos` | `1` | QoS 级别（0/1/2） |
| `keepalive` | `60` | 心跳（秒） |
| `publish_mode` | `single` | 发布模式：`single` / `batch` |
| `adapter` | `standard` | 适配器名称或客户编号（如 `C001`） |
| `adapter_config` | `{}` | 适配器专属配置 |
| `command_timeout` | `30.0` | 命令执行超时（秒） |

**适配器系统**：支持多客户协议适配，通过 `GET /api/channels/adapters/list` 查询所有可用适配器，通过 `GET /api/channels/adapters/{adapter_code}/defaults` 获取默认配置。

**依赖**：`aiomqtt`

#### 5.2.2 XNC 客户端

**插件名**：`xnc`

**用途**：对接 XNC 平台，使用 Protobuf 协议通信，支持命令下行与结果回传。

### 5.3 过滤器插件（Filter）

过滤器在数据流转管线（Pipeline）中执行，按顺序处理每个数据点。

| 插件名 | 用途 | 典型场景 |
| --- | --- | --- |
| `dedup` | 去重 | 去除相邻重复读数，减少上行流量 |
| `scale` | 缩放 | 比例偏移变换（如 4-20mA 工程量转换） |
| `rename` | 重命名 | 字段名映射、规范化 |

### 5.4 规则插件（Rule）

规则插件用于评估数据是否满足触发条件。

| 插件名 | 用途 |
| --- | --- |
| `threshold_rule` | 阈值比较，支持 `>` `<` `>=` `<=` `==` `!=` 操作符与持续时间 |
| `expression_rule` | 基于 AST 的安全表达式评估，支持数学/比较/逻辑运算 |
| `schedule_rule` | 基于 cron 或时间间隔触发 |

### 5.5 投递插件（Delivery）

规则触发后的通知与动作执行。

| 插件名 | 用途 | 关键配置 |
| --- | --- | --- |
| `email` | SMTP 邮件通知 | `smtp_host` / `smtp_port` / `smtp_user` / `smtp_password` / `from_address` / `recipients` / `use_tls` / `use_ssl` |
| `webhook` | HTTP Webhook 推送 | `url` / `method`（POST/PUT/GET）/ `headers` / `timeout` / `retry_count` |
| `action` | 下发设备控制命令 | `target_service` / `target_asset` / `operation`（`write_setpoint` / `execute_operation`）/ `point` / `value` / `delay` |
| `system` | 系统内建告警 | 生成活跃告警记录，供 Web UI 告警中心展示 |

## 6. 设备管理

### 6.1 设备模型

设备（Device）是 XAgent 中描述一个现场设备的顶层实体：

```json
{
  "asset": "modbus_device_001",       // 资产标识（唯一，仅字母数字下划线连字符，≤64字符）
  "name": "1号Modbus设备",
  "description": "车间温湿度采集",
  "enabled": true,
  "status": "active",                  // active / inactive / maintenance / error
  "plugin": {
    "name": "modbus_tcp",
    "config": {                        // 插件实例配置，覆盖默认值
      "host": "192.168.1.10",
      "port": 502
    }
  },
  "points": [                          // 点位列表
    {
      "name": "temperature",
      "data_type": "float",
      "standard_data_type": "float",   // 自动推导：bool/int/float/string
      "unit": "°C",
      "enabled": true,
      "config": {},                    // 协议特定配置
      "metadata": {},                  // 元数据（如报警阈值）
      "tags": []
    }
  ],
  "metadata": {},
  "tags": []
}
```

### 6.2 设备生命周期

1. **创建设备** → 自动生成配置文件并入库
2. **加载插件实例** → 启动采集
3. **运行中** → 定期轮询点位数据
4. **修改配置** → 需调用 reload 接口热重载
5. **删除设备** → 停止插件、软删除数据库记录

### 6.3 设备发现

针对 BACnet 设备，XAgent 提供自动发现能力：

1. **获取可用网卡**：`GET /api/devices/network-interfaces`（多网卡环境下建议指定 `interface_ip`）
2. **广播发现设备**：`POST /api/devices/discover/bacnet`（发送 Who-Is，等待 I-Am 响应）
3. **发现设备点位**：`POST /api/devices/{asset}/discover-points`（自动读取对象列表与属性）
4. **批量导入点位**：`POST /api/devices/{asset}/points/batch`

> ⚠️ BACnet 设备发现总超时为 60 秒，请合理设置 `timeout` 参数（≤30 秒/次）。

### 6.4 设备热重载

修改点位配置后无需重启服务，调用 reload 接口即可生效：

```bash
# 重载单个设备
POST /api/devices/{asset}/reload

# 批量重载
POST /api/devices/reload
```

### 6.5 设备导入导出

支持设备配置的 JSON 导入导出，便于跨环境迁移：

```bash
# 导出（可指定 asset 列表）
POST /api/devices/export

# 导入
POST /api/devices/import?overwrite=true
```

## 7. 北向通道

### 7.1 通道配置

北向通道（North Channel）是上行数据的统一抽象，目前支持 MQTT 与 XNC 两种协议。

```json
{
  "id": "mqtt_channel_01",
  "name": "主MQTT通道",
  "description": "上行到中心MQTT",
  "protocol": "mqtt",                  // mqtt / xnc
  "enabled": true,
  "status": "active",
  "config": {                          // 协议特定配置
    "broker": "mqtt.example.com",
    "port": 1883,
```

## 8. 规则引擎

### 8.1 核心概念

| 概念 | 说明 |
| --- | --- |
| **Rule（规则）** | 一条完整的业务规则，包含触发条件与通知配置 |
| **Pipeline（管线）** | 过滤器链，定义数据处理流程（南向管线/北向管线） |
| **Channel（通知通道）** | 规则触发后的通知通道，绑定到投递插件（email/webhook/...） |
| **Subscription（订阅）** | 规则订阅的数据源（设备/点位） |

### 8.2 规则创建流程

1. **创建通知通道**：`POST /api/rules/channels`（绑定 email/webhook 等投递插件）
2. **创建管线（可选）**：`POST /api/rules/pipelines`（定义数据处理流水线）
3. **创建规则**：`POST /api/rules`（关联规则插件、订阅源、通道）
4. **绑定通道**：`POST /api/rules/{rule_id}/channels`

### 8.3 规则配置示例

```json
{
  "id": "high_temp_alert",
  "name": "高温告警",
  "description": "温度超过30°C持续60秒触发告警",
  "enabled": true,
  "plugin": {
    "name": "threshold_rule",
    "config": {
      "threshold": 30,
      "operator": ">",
      "duration": 60
    }
  },
  "data_subscriptions": [
    {
      "asset": "modbus_device_001",
      "point_name": "temperature"
    }
  ],
  "notification": {
    "title": "高温告警",
    "message": "设备 ${asset} 温度 ${value}°C 超过阈值",
    "level": "warning"
  },
  "pipeline_id": null,
  "channel_ids": ["email_channel_01", "webhook_channel_01"]
}
```

### 8.4 规则状态查询

- `GET /api/rules/status`：规则引擎整体状态
- `GET /api/rules`：列出所有规则（含执行次数、最后触发时间）
- `GET /api/rules/{rule_id}`：单个规则详情

### 8.5 管线（Pipeline）

管线用于将多个过滤器串联执行，支持南向（south）和北向（north）两个位置：

```json
{
  "pipeline_id": "filter_pipeline_01",
  "filters": [
    {"name": "dedup", "config": {"window": 5}},
    {"name": "scale", "config": {"factor": 0.1, "offset": 0}}
  ],
  "continue_on_error": true,
  "log_errors": true,
  "max_retries": 3,
  "retry_delay": 1,
  "retry_backoff": 2.0,
  "timeout_per_filter": 10,
  "location": "south",
  "service_name": "modbus_tcp",
  "enable_metrics": true
}
```

### 8.6 表达式规则

`expression_rule` 插件支持基于 AST 的安全表达式评估：

- 允许运算：`+ - * / % ** //`、比较 `> < >= <= == !=`、逻辑 `and or not`
- 禁止操作：函数调用、属性访问（防止代码注入）
- 变量来源：订阅的数据点位

示例表达式：`(temp - 32) * 5 / 9 > 30 and humidity < 80`

## 16. 常见问题

### 16.1 启动相关

**Q1：启动报错 `bacpypes3 is not installed`？**
A：Linux 平台需显式安装 `bacpypes3==0.0.106`，Windows 可通过 `pip install bacpypes3` 安装最新版。

**Q2：Windows 启动时 WinError 10038？**
A：XAgent 已内置 `patch_windows_selector` 修复此问题，正常情况下无需处理。若仍出现，请确认使用 Python 3.10+。

**Q3：如何修改默认数据目录？**
A：按优先级使用：命令行 `--data-dir` > 环境变量 `APP_DATA_DIR` > 平台默认路径。

### 16.2 设备采集

**Q4：BACnet 设备发现一直超时？**
A：
1. 确认主机与 BACnet 设备在同一广播域
2. 多网卡环境下通过 `GET /api/devices/network-interfaces` 选择合适网卡，并在发现请求中指定 `interface_ip`
3. 总超时上限为 60 秒，可分多次小范围发现

**Q5：Modbus 设备读取失败？**
A：
1. 检查 `host` / `port` / `slave_id` 是否正确
2. 确认点位 `function_code` 与寄存器类型匹配（ coils=1 / discrete_input=2 / holding=3 / input=4 ）
3. 检查 `byte_order` 与数据类型对齐

**Q6：KNX 网关连接数满？**
A：将 `connection_type` 改为 `routing`，使用多播通信不占用连接槽（需 KNX 网络支持多播）。

### 16.3 规则引擎

**Q7：规则未触发？**
A：
1. 检查规则 `enabled` 是否为 true
2. 确认 `data_subscriptions` 中的 asset / point_name 与实际设备一致
3. 阈值规则需考虑 `duration`（持续时间）参数
4. 查看 `GET /api/rules/{rule_id}` 的 `execution_count` 与 `last_triggered`

**Q8：邮件通知发送失败？**
A：
1. 通过 `POST /api/rules/channels/{channel_id}/test` 单独测试通道
2. 确认 SMTP 端口与 TLS/SSL 配置匹配（587+STARTTLS / 465+SSL）
3. 检查发件邮箱是否开启 SMTP 授权

### 16.4 性能与维护

**Q9：数据库文件过大？**
A：
1. 调小 `storage.retention_days`（如 1-7 天）
2. 调大 `storage.cleanup_interval`（避免频繁清理影响采集）
3. 定期调用 `POST /api/storage/vacuum` 压缩数据库
4. 通过 `GET /api/storage/size` 监控增长趋势

**Q10：如何排查性能问题？**
A：
1. 查看 `GET /api/system/stats` 的 CPU/内存使用
2. 查看 `GET /api/stats` 的 buffer `pending_count`（持续偏高说明写入跟不上）
3. 调整 `storage.batch_size` 和 `flush_interval`
4. 查看 `GET /api/data/quality` 的 `quality_rate`（数据质量低需检查通信）

### 16.5 安全

**Q11：默认 Token 是否安全？**
A：默认 Token `xagent_47808` 仅供测试。生产环境务必通过环境变量 `XAGENT_API_TOKEN` 设置强随机 Token，并配合用户权限系统使用。

**Q12：Web UI 是否支持多用户？**
A：支持。通过 `/api/users` 接口创建多用户，并通过角色权限矩阵控制各用户的访问范围。
